# EXP010: Join Order

**Category:** Joins  
**Difficulty:** Advanced  
**Tags:** JoinOrder, Cardinality, ForceOrder

## Description
Compares a forced three-table self-join order with optimizer-selected ordering.

## Problem Statement
A poor join order can create large intermediates before selective predicates reduce rows.

## Expected Outcome
The optimizer-selected order may lower intermediate work, but the result must remain equivalent.

## Performance Theory
Join order and cardinality estimates influence the size and cost of intermediate results.

## Diagnostic Expectations
Compare reads, CPU, elapsed time, and plan estimates; this dataset's self-join remains intentionally bounded.

## Plan Expectations
Inspect join sequence and operator inputs. `FORCE ORDER` is used only as an experiment control.
