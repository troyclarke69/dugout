# EXP008: Merge Join

**Category:** Joins  
**Difficulty:** Advanced  
**Tags:** MergeJoin, HashJoin, Join

## Description
Compares a forced Merge Join with a Hash Join for the same selective customer self-join.

## Problem Statement
Merge joins require ordered inputs; obtaining that order may introduce sorts.

## Expected Outcome
The result is identical, while the chosen strategy exposes the cost of input ordering versus hashing.

## Performance Theory
When both inputs are suitably ordered, merge joins can process them as streams. Otherwise, sort work can dominate.

## Diagnostic Expectations
Inspect sort operators, reads, CPU, elapsed time, and memory grants.

## Plan Expectations
The baseline requests Merge Join; inspect whether SQL Server inserts Sort operators before it.
