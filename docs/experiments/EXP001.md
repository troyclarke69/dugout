# EXP001: Non-SARGable Date Filter

**Category:** SARGability  
**Difficulty:** Beginner  
**Tags:** Date, Predicate, Index Seek

## Description
Compares a year-extraction predicate with an equivalent half-open date range against `dbo.Orders`.

## Problem Statement
Applying `YEAR()` to the indexed column can prevent a direct range seek.

## Expected Outcome
The range predicate should qualify for an index seek and touch fewer pages when the supporting date index is present.

## Performance Theory
A SARGable predicate lets SQL Server navigate an index using a search argument instead of evaluating a scalar expression for each row.

## Diagnostic Expectations
Expect fewer logical reads and often lower CPU and elapsed time. Physical reads and scan count depend on cache and plan details.

## Plan Expectations
The baseline is scan-oriented; the optimized plan may use an Index Seek. Costs depend on available indexes and SQL Server version.
