# EXP014: Skewed Data Distribution

**Category:** Parameter Sniffing  
**Difficulty:** Advanced  
**Tags:** Skew, Cardinality, ParameterSniffing

## Description
Builds an isolated 100,000-row table where CustomerId 1 owns 95% of rows, then compares literal and parameterized hot/cold counts.

## Problem Statement
A single average-density estimate may poorly represent highly skewed values.

## Expected Outcome
Hot and cold counts match between variants while estimates and access strategies may differ.

## Performance Theory
Histograms model value distribution, but parameter compilation and reuse determine which value informs a cached plan.

## Diagnostic Expectations
Compare estimated versus actual rows in runtime XML, reads, CPU, and elapsed time.

## Plan Expectations
The query contains hot and cold predicates. The table is isolated and removed by cleanup; no production table is altered.
