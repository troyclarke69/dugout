# EXP006: Composite Index Key Ordering

**Category:** Indexing  
**Difficulty:** Advanced  
**Tags:** CompositeIndex, KeyOrder, SARGability

## Description
Adds an index keyed by CustomerId then OrderDate and compares converted/year predicates with direct ranges.

## Problem Statement
Composite indexes are ordered by their leading key; a predicate on a later key alone may not navigate the index effectively.

## Expected Outcome
The direct predicates should be more seekable, with CustomerId constraining the leading key and OrderDate the following key.

## Performance Theory
The leftmost-prefix rule affects navigation. Residual predicates can still be evaluated after a seek.

## Diagnostic Expectations
Compare logical reads and inspect seek predicates versus residual predicates.

## Plan Expectations
The optimized query may use a composite seek. The setup index is removed in cleanup.
